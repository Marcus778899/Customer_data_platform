### F-1 本機 .env 兩把金鑰相同時，後端啟動失敗，錯誤訊息在 log 內為亂碼（minor）
- 重現：1. `.env` 的 `CDP_INGEST_API_KEY`、`CDP_ADMIN_API_KEY` 設成同值 2. `make api-run`
- 實際：`IllegalStateException: cdp.security.ingest-api-key �P cdp.security.admin-api-key ���i�ۦP...`（中文變亂碼，Windows Git Bash 導向檔案時）；拒絕啟動本身符合規則
- 預期：訊息可讀
- 備註：我不能改 `.env`，改以 make 命令列覆寫啟動。

### F-2 事件篩選／條件的欄位列在側欄 1440 寬被擠到看不清（major）
- 重現：1. 畫布選進入條件 2. 事件名稱填 `cart_item_added`、「加入第一個條件」 3. 欄位選「手動輸入欄位代碼…」，輸入 `cart_total`，比較選「大於」填 500
- 實際：欄位下拉只露出「手動輸,」、比較下拉只露出「（選」「大於」，欄位代碼輸入框縮成約 28px 寬、輸入的 `cart_total` 完全看不到，「properties.」前綴斷成兩行。條件節點（會員等級／屬於其中之一）同樣被截斷（「會員等級」只見「會員等紀」）
- 預期：下拉與欄位代碼能讀到完整內容（設計稿要求欄位一行、比較＋值一行）
- 截圖：`docs/uat/v0.3.0/event-filter-invalid-code-1440.png`、`event-filter-nonnumeric-1440.png`、`canvas-condition-filled-1440.png`

### F-3 畫布新增節點跑到畫面外、不自動排版，「符合視窗大小」沒用、重新整理後縮成 30%（major）
- 重現：1. 進編輯畫布 2. 依序按工具列加入 14 個節點（等待、條件、訊息…）
- 實際：新節點排成一整列，出現在可視範圍右側外，畫面沒有捲過去；按「⤢ 符合視窗大小」沒有變化（仍 80%）；重新整理後縮放變 30%，節點文字小到無法閱讀，最左與最右節點仍被切；接線後也沒有分層排版（設計規定 dagre 由左到右）。小地圖是空白塊
- 預期：新節點可見、整張圖可讀、符合視窗有效
- 有繞法：用面板下拉接線、點節點操作（我用這種方式建圖）；但使用者看不到自己建的圖
