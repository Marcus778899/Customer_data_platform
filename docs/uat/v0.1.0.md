## 發現

### F-1 session 失效後導回登入，沒有「登入已逾時，請重新登入」提示（major；FIX-06 後已修正，見下方重測）
- 重現：1. 登入並查詢任一客戶 2. 後端重啟（讓 session 失效） 3. 在列表按「重試」。
- 實際：導向 `/login?next=%2F%3Fq%3D01UATPROFILEALICE00000000A`，登入頁是空白表單，沒有任何說明；使用者不知道為什麼被登出。console：`Failed to load resource: the server responded with a status of 401 (Unauthorized) @ /api/v1/auth/me`（或列表 API）。
- 預期：規格「登入／成功」欄寫明 session 逾時顯示「登入已逾時，請重新登入」；設計稿也有此狀態（`login-session-expired` 區段）。
- 備註：回原頁（含 `?q=`）是正確的。
- 截圖：`docs/uat/v0.1.0/s19-session-expired.png`

#### 重現細節（2026-10-18 真瀏覽器 Playwright Chromium，dev server；api 以 make 命令列覆蓋臨時帳密）
結論：F-1 只在「頁面重新載入後第一個請求是 `/auth/me` 且回 401」時重現；只要 401 來自 `/enrollments` 列表請求，提示就會顯示。dev 模式（React StrictMode）每次載入 `/me` 與列表各送兩次，下表已合併註明。

| 情況 | 操作 | 請求順序（路徑＋狀態） | 最後畫面 | 逾時提示 |
|---|---|---|---|---|
| (a) | 登入、查詢 alice；後端重啟完成；按「查詢」（列表沒有錯誤時不會有「重試」鈕，只有錯誤框才有，故以再查詢代替） | `/enrollments?q=…` 401 → 導向 `/login?next=%2F%3Fq%3D…`（之後沒有 `/me`） | 登入頁，頂端有藍色提示「登入已逾時，請重新登入／登入後會回到剛才的頁面。」 | 有（`f1-a-after-query.png`） |
| (b) | 登入、查詢；停後端；按「查詢」→ 錯誤框「查詢失敗，沒有取得資料」＋「重試」；再按「重試」；啟動後端；再按「重試」 | `/enrollments?q=…` 502 → `/enrollments?q=…` 502 → `/enrollments?q=…` 401 → 導向登入頁（全程沒有 `/me`） | 同 (a)，有提示 | 有（`f1-b-1-backend-down.png`、`f1-b-2-after-retry.png`） |
| (c) | 登入、查詢；後端重啟完成；重新載入同一網址（`/?q=…`） | `/auth/me` 401、`/auth/me` 401（StrictMode 兩次；列表請求不會送出）→ 導向 `/login?next=…` | 登入頁是空白表單，沒有任何提示 | 沒有（重現 F-1；`f1-c-after-f5.png`） |

- 另一對照：重新載入前整段請求為 `/auth/me` 200 ×2、`/enrollments` 200 ×2，沒有其他 401。
- 所以 F-1 的實際成因與「後端重啟」本身無關，而是 `/me` 401 時提示被清掉：凡在 session 已失效的情況下重新整理或直接開網址（含關閉後重開、書籤），都不會看到提示；而分頁一直開著、閒置到逾時後才操作，才會看到提示。實務上閒置逾時後使用者多半會重新整理或從書籤進入，所以 F-1 影響面比 (a)(b) 看起來大。
- 注意事項：Playwright 的 `F5` 按鍵沒有觸發重新載入，(c) 改以對同網址再次 navigate（等同重新載入）；console 每次 401／502 皆有瀏覽器自動記的 `Failed to load resource`，無程式錯誤。

**自己啟動與登入（變數名稱即可，不寫值）**
1. `python3 scripts/check_env.py`，在 `.env` 補齊缺少的變數；登入帳密為 `CDP_SUPPORT_USERNAME`、`CDP_SUPPORT_PASSWORD`；建旅程用 `CDP_ADMIN_API_KEY`、送事件用 `CDP_INGEST_API_KEY`；要看到 cart_id 一類明文欄位需設 `CDP_TRACE_PLAIN_KEYS`；埠號為 `API_PORT`、`WEB_PORT`。
2. `make setup`、`make infra-up`；另開兩個終端機各跑 `make api-run`、`make web-dev`。
3. 以 `Authorization: Bearer <CDP_ADMIN_API_KEY>` 對 `/api/v1/journeys` 建旅程（契約 §3.1），再以 `Authorization: Bearer <CDP_INGEST_API_KEY>` 對 `/api/v1/events` 送事件（契約 §3.2、spec 01 §8；`identity.profile_id` 必填）。
4. 瀏覽器開 `http://localhost:<WEB_PORT>/`，以 `CDP_SUPPORT_USERNAME`／`CDP_SUPPORT_PASSWORD` 登入。
