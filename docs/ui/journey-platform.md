## 圖形軌跡與迴圈的呈現
- 節點三態：已經過＝綠框＋「✓ 已經過」；目前位置＝琥珀粗框＋「● 目前位置」；未經過＝虛線框（讀屏文字「未經過」）。走過的邊用藍粗線，未走的邊虛線
- 迴圈：回到前面節點的邊畫成節點下方繞回的點狀線，標「再等一輪」。同一節點多次經過，節點上標「步驟 6、8」，逐步紀錄標「第 2 次經過」，目前停在第 2 圈
- 客戶依舊版執行時，頁面顯示「此客戶依 v2 執行；最新為 v3」，圖畫的是 v2（版本不可變，spec 03 §1）
- 圖加文字版：節點清單（畫布）與逐步紀錄（軌跡）內容等價，圖載入失敗時軌跡頁退回逐步紀錄
## 狀態
| 畫面 | 空 | 載入中 | 錯誤 | 成功 |
|---|---|---|---|---|
| 登入 | 空白表單 | 「登入中…」欄位唯讀 | 「帳號或密碼不正確」（唯一一種）；逾時「登入已逾時，請重新登入」 | 回原頁；多工作區先選擇 |
| 旅程列表 | 無旅程：建立第一個旅程（檢視者無按鈕）；篩選無結果：清除搜尋 | 骨架列 | 紅色提示＋代碼＋重試 | 表格＋筆數 |
| 畫布 | — | 骨架 | 404「找不到」；5xx 重試；編輯衝突：載入他人版本或下載我的修改 | 圖＋面板 |
| 客戶搜尋 | 初始：說明可輸入什麼；查無：列可能原因 | 「搜尋中…」 | 空字串：請輸入；5xx 重試 | 結果表（遮罩徽章） |
| 客戶頁／軌跡 | 尚無旅程：說明何時會出現 | 骨架 | 404 與 5xx 分開寫，皆附代碼 | 終態另顯示結束時間與原因 |
## 互動
| 操作 | 結果 | 回饋 |
|---|---|---|
| 切換工作區 | 清除搜尋與篩選，回該工作區列表；有未儲存修改先確認 | 「正在切換…」；失敗仍留原工作區並提示 |
| 點節點 | 右側開啟設定（編輯模式可改） | 焦點移到面板標題；「關閉」回到節點 |
| 編輯連線／加節點 | 拖曳或「加入」按鈕、出口目標用下拉選（不需拖曳） | 圖上紅框＋「⚠ 有錯誤」，面板「定位節點」 |
| 搜尋客戶 | 網址同步 `?q=`；唯一一筆是否直進客戶頁見待決定 | 完成後焦點到結果標題 |
| 勾選「同時顯示 UTC 原值」 | 時間旁加 UTC | 預設本地時區（D-016） |
遮罩沿用 v0.1.0：只有後端標記的值顯示「已遮罩」，無法解除，不提供複製；ID 可複製。
## 窄螢幕與中螢幕
- 1024px 以下：側欄改頂列（品牌、選單鈕、工作區）；1100px 以下兩欄改單欄。640px 以下：表格轉卡片、篩選與搜尋欄位堆疊，互動元件（按鈕、連結、篩選標籤、勾選、選單項）高 >= 44px，圖左右捲動並提示改看文字版。一併修正 #51（登入欄位間距）、#66（800px 欄位擠壓、375px 觸控目標），已套用到 v0.1.0 設計稿
- 畫布編輯建議桌面使用；窄螢幕只保證可檢視，不保證可拖曳（連線可用下拉完成）
## 無障礙
- 對比：側欄、節點類別色、軌跡色均已核算，文字 >= 4.5:1、邊框與圖形 >= 3:1；狀態一律有文字，不只靠顏色
- 鍵盤：圖卡片是 `<button>`（`aria-pressed`），Tab 依閱讀順序；拖曳皆有替代操作；縮放 + / − / 0；工作區選單與窄螢幕選單用 `details`，實作時補 Esc 關閉
- 讀屏：圖區 `role="group"` 並說明可捲動；邊與裝飾 SVG `aria-hidden`；軌跡逐步紀錄用 `<ol>`，目前步驟 `aria-current="step"`；載入 `role="status"`、錯誤 `role="alert"`；尊重 `prefers-reduced-motion`
## 待甲方決定／需要調查
- 待決定：(1) 角色與權限（設計稿暫用檢視者／編輯者，是否有核准者、誰能送審）；(2) 產品名稱與品牌色（暫「客戶旅程平台」、中性藍灰）；(3) 搜尋是否支援前綴／部分比對（暫完全比對）；(4) 搜尋唯一一筆是否直進客戶頁（延續 UAT F-8）；(5) 導覽是否再放訊息範本、報表、設定佔位（目前只有旅程管理、客戶、受眾）；(6) 列表是否要「進行中人數」與各狀態筆數（要後端聚合）；(7) 含迴圈旅程是否限制最大圈數，或在畫布上警示；(8) 拆版：P0 先發、P1 後發是否可接受
- 需調查（轉 architect／DESIGN-03）：(1) 旅程定義節點沒有座標欄位（spec 03 §4），畫布要存位置或自動排版？(2) 旅程列表、定義、版本 API 欄位（狀態、updated_by、進行中人數）；(3) 軌跡每步的 visit 序號、出口、`decisionReason`、`evaluated` 與依 Enrollment 版本取定義；(4) 搜尋：email、手機以雜湊索引完全比對？手機正規化為 E.164？回傳 `match_field`；(5) 客戶頁屬性白名單（D-021）含哪些、姓名是否存在；(6) 使用者、工作區成員、角色、工作區切換與 session 逾時；(7) 草稿儲存衝突偵測與驗證結果格式（含 spec 03 §6 規則編號、節點 id）
- 需調查（researcher）：圖形畫布函式庫（如 React Flow／xyflow、dagre）的授權、鍵盤無障礙、自動排版與回邊（迴圈）支援；研究紀錄查不到業界迴圈畫法，本稿為自訂，建議用戶測試
