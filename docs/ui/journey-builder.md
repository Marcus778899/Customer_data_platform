## 事件篩選（`event_filter`，D-085；契約 `journeys.md` §4）
- 位置：進入條件、等事件面板的「只讓符合條件的事件進入／只算符合條件的事件（選填）」區塊，版型與條件節點同一套（一行一句、`全部符合／任一符合`、「但不可以是…」群組、最多 5 層）；差異只有一項：欄位只列**事件屬性**，不列客戶資料。
- 白話句：區塊頂端一句即時摘要（例：只有「購物車金額」大於 500 的「加入購物車」事件，才會讓客戶進入這個旅程）；進入條件與等事件的句尾不同（等事件寫「其他事件不算等到，繼續等到逾時」）。每個條件的欄位代碼、比較代碼、值放「進階資訊」（`event_filter：properties.cart_total ・ GT ・ 500`）。
- 節點卡：無篩選維持原摘要；1 項寫「只限〈句〉」（單行截斷）；2 項以上寫「只限／只算符合 N 項條件」；驗證有錯沿用紅框＋「有錯誤」。
- 新增：空狀態（`ef-states`）有說明與「加入第一個條件」；欄位下拉列「這個事件的屬性」（`field-keys` 的 `event_properties`，依事件名稱），最後一項「手動輸入欄位代碼…」（`properties.` 前綴固定，只填 `^[a-z][a-z0-9_]*$`）。欄位名稱用前端內建白話對照，沒有的顯示原代碼。條件未填完不寫入草稿。
- 編輯：改欄位會重設比較與值；比較只留該欄位適用者（數字欄：大於／至少／小於／至多／等於…；文字欄：等於、不等於、包含、是其中之一…；沒有值的：有填、沒填）；`IN`／`NOT_IN` 的值用逗號分隔。事件名稱改變時保留已填條件（欄位建議重載）。
- 刪除：每個條件有移除鈕；移除最後一個或按「清除篩選」回到空狀態（寫 `null`），不彈確認，頁內顯示「已清除 N 項條件」＋「復原」。進入條件節點本身不可刪除（旅程需要入口）。
- 驗證錯誤（`ef-errors`）：欄位旁行內錯誤（紅框＋圖示＋文字、`aria-invalid`）：數字比較填非數字、欄位未選、值未填、手動欄位代碼格式不符；契約驗證才抓得到的：欄位不是 `properties.<鍵>`（客戶資料）、`behavior`／`segment` 葉節點（顯示「不支援的條件」只能移除）、超過 5 層。驗證結果清單照 `ed-validate`，「定位節點」開面板並捲到該條件；`field` 路徑收進進階資訊。
- 載入與失敗：欄位建議載入中只有欄位選單顯示骨架；失敗或 3 秒未回顯示警告條＋重試，仍可手動輸入；事件名稱未填時提示先填，仍可手動輸入。
- 無障礙與窄螢幕：欄位清單 `role="listbox"`、方向鍵選擇、Esc 關閉；摘要句 `aria-live="polite"`；錯誤 `role="alert"` 並以 `aria-describedby` 綁欄位；移除鈕 `aria-label`「移除這個條件」；窄螢幕互動元件 >= 44px，句子欄位直向堆疊（欄位一行、比較＋值一行）。
## 審核可見性（完整矩陣見 `rv-matrix`）
停用鈕一律保留並附原因（`aria-disabled`＋`aria-describedby`，仍可聚焦）。檢視者：只能看。編輯者：編輯、送審、捨棄草稿、停止；送審中只能撤回自己送的。管理員：另可核准、退回、撤回任何人送的；自己送的核准停用並說明（D-060）。每次發佈都審；停止不審但寫入紀錄；`DRAFT` 旅程停用「捨棄草稿」「停止」。管理金鑰建立只出現在紀錄（D-061）。

## 無障礙與窄螢幕
載入＝骨架（`role="status"`）；錯誤＝`role="alert"`＋請求編號＋重試；權限不足＝停用鈕附原因或整頁 403。對話框 `role="dialog" aria-modal`，焦點進入第一欄、Esc 取消、回到觸發鈕。圖：節點是 `<button>`，選取 `aria-pressed`；邊與裝飾 `aria-hidden`；每張圖附「文字版節點清單」。狀態一律文字＋顏色＋圖示；對比 >= 4.5:1；reduced-motion 關閉轉場。
窄螢幕：≤1100px 面板排到圖下方；≤640px 工具列與按鈕堆疊、表格／矩陣轉卡片、互動元件 >= 44px；畫布以左右捲動檢視，編輯建議桌面，審核與停止在窄螢幕可完成。
