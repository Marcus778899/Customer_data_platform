## 畫面（詳情，由上而下）
1. 麵包屑（客戶／姓名或遮罩／旅程進度）、h1「『旅程名』旅程的進度」、副標「客戶：…・加入時間」、狀態徽章、重新整理＋「今天 10:00 更新」
2. 摘要卡（`role="status"`，左側色條＝狀態色）：「這位客戶現在在哪？」「接下來會發生什麼？」「訊息有送出嗎？」，答案粗體一句＋補充一句，不用術語
3. 走過的步驟：垂直時間軸，每步＝圖示＋白話標題＋狀態字（已完成、目前在這裡、接下來、發生問題、已中止）＋一句說明＋時間；「接下來」來自該 Enrollment 綁定版本的旅程定義，取不到就不顯示（降級，仍可用）
4. 訊息發送紀錄：時間、哪一步、管道、結果；無資料時說明何時會出現
5. 進階資訊（`details`）：進度編號（可複製）、客戶 ID、旅程 ID、版本、技術名稱、UTC 原值、`as_of`、判斷值、系統原因文字、觸發事件、遮罩欄位
清單頁：改稱「旅程進度」，欄位＝客戶、旅程、狀態、目前在哪一步、下一步；ID 不當欄位，查詢框標「客戶 ID 或進度編號」。

## 摘要組句（前端由 `status`、`wake_condition`、`trace`、`delivery_history`、旅程定義組出）
| 情況 | 在哪 ／ 接下來 ／ 訊息 |
|---|---|
| WAITING TIMER | 在「X」，已等 N／預計 `wake_at` 之後自動繼續，下一步是「Y」／還沒走到發送（有已送出的就寫哪一則） |
| 走完＋有 PENDING 發送 | 旅程已走完／不會再有新步驟，N 則訊息排隊／還沒有送達，超過 10 分鐘請聯絡技術人員 |
| 走完＋SENT | 旅程已走完／沒有後續／「X」已於時間送出 |
| FAILED | 停在「X」因為發生錯誤／不會自動繼續，請勿重複操作／失敗原因＋「複製診斷資訊」 |
| ABORTED | 進度已中止／不會再有任何步驟（旅程停止時間）／沒有，之後也不會 |
| ACTIVE／PENDING | 處理中，通常幾秒內到下一步（不顯示時間） |
| WAITING EVENT／SIGNAL（v0.3.0） | 在等客戶做「X」／最晚 `timeout_at` 之後改走「沒等到」 |
步驟標題由節點型別組：EventSourceNode＝「＜節點名＞，進入旅程」、WaitDelayNode＝「等 3 天」（ISO 期間轉中文）、SendMessageNode＝「發送訊息：＜節點名＞」、EndNode＝「旅程結束」、StartNode 不顯示；`node_name` 為 null 才退回型別白話名（「發送訊息」）。完整對照（狀態、發送結果、略過原因、出口、欄位名、v0.3.0 節點）見 `plain.html#glossary`。時間規則見 `plain.html#time`。

## 狀態與互動
- 載入：骨架（摘要卡預留三列高度）；404：「找不到這筆進度」＋錯誤代碼＋回客戶搜尋；5xx 同列表錯誤；定義取不到：警示條＋重試，只列已走過的步驟；遮罩：只有 `masked_paths` 的值標「已遮罩」且不可解除、不可複製
- 重新整理重打同一請求並更新「更新於」；進階資訊用原生 `details`；「複製診斷資訊」只含進度編號、時間、`request_id`，不含個資；沒有寫入操作（D-005）
- 登入、查詢驗證與錯誤文案沿用 v0.1.0（`index.html`）
## 窄螢幕與無障礙
- < 640px：摘要卡單欄（圖示縮為 32px）、表格轉卡片（`data-l` 欄名）、按鈕與輸入 >= 44px、`dl` 單欄；500px、375px 已用 iframe 驗證無橫向捲動
- 狀態一律文字＋顏色＋圖示；時間軸 `<ol>`、目前步驟 `aria-current="step"`；摘要 `role="status"`；對比 >= 4.5:1；進階資訊 summary 可鍵盤操作；h1 在換頁後取得焦點；尊重 reduced-motion

| 項目 | 決定 |
|---|---|
| 首屏版型 | 三問摘要卡，不用儀表板或圖表；答案用 `--text-lg` 加粗 |
