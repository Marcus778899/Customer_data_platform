## 審核（D-056、D-060、D-061；契約 `journeys.md` §3.2、§3.3）

| 4 | 退回必附原因（1–200 字）；退回、撤回後草稿回到可編輯，改完可再送審，每次送審一筆新紀錄 | D-056 |

## 版本綁定（spec 02 §2）

- 客戶進入旅程時綁定當下最新版本，之後核准新版本不影響已在旅程中的客戶：v1 等待中的客戶照 v1 走完，新進入的走 v2

## 停止（D-060 2A；`journeys.md` §3.5、spec 05 §5）

- 編輯者以上可直接停止，不經審核；必附原因；留下誰、何時、原因
- 立即不再接受新進入；尚未送出的訊息全部取消、不會再發出；進行中的旅程進度由背景逐步轉為「已停止」
- 不可恢復；要重新開始須另建旅程。停止時送審中的審核自動撤回（原因「旅程已停止」）
- 尚未發佈過的旅程（草稿）不能停止

## 節點（`journeys.md` §4）

| 節點 | 規則 |
|---|---|
| 等待事件 | 等指定事件發生走「發生」；設了逾時則到時走「逾時」；不設逾時又沒有全域退出時畫布提醒（spec 03 §6 規則 12） |
| 條件判斷 | 依客戶屬性或觸發事件屬性判斷，走「是」或「否」；判斷原因不寫出屬性值（避免個資外洩），值放在可遮罩的判斷值 |
| 分流（SplitTest） | 依權重（總和 100）把客戶分組，同一客戶重複推進分組不變；v0.3.0 只做分流，不做成效分析（#157） |
| 匯流、提前離開、達成目標 | 匯流接回一條；提前離開需寫原因；目標節點與 `settings.goal` 皆記為達成目標 |
| 迴圈 | 允許，不限圈數（D-050），但每個迴圈必須含等待節點，否則不能送審（規則 7） |
| 重複進入 | 依 `settings.reentry`；同一觸發事件重送只建一筆（G3）；以 `cart_id` 等去重鍵設定時，同鍵只建一筆 |

## 遮罩（D-014、D-021、D-082、#184）

- 白名單：只有明文清單上的鍵顯示原值，其餘一律遮罩（新欄位漏列也不外洩，D-021）
- 程式內建預設明文清單 = 姓名（`name`）；email、手機與其他屬性、識別碼皆遮罩。新環境不做任何設定即如此（#184）
- `.env` 能否、如何調整明文清單：待決定 1（DESIGN-05）
- 所有角色看到的遮罩相同；不提供解除遮罩
