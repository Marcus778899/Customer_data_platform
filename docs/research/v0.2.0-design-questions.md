# v0.2.0 設計待查題（DESIGN-03，研究日 2026-10-19）
**結論（事實整理，非決策）**
1. PG18：CREATEROLE 本身不能授予 BYPASSRLS；建 BYPASSRLS 角色需 superuser（兩頁說法略有出入）。Azure 僅 PG16+ 可建；RDS、Cloud SQL 查不到。
2. PG18：pg_stat_slru 的 name 值為 `subtransaction`（非 Subtrans）；pg_stat_activity 無子交易欄位，改用 `pg_stat_get_backend_subxact()`，欄位為 `subxact_overflow`。
3. Spring Security 7.0 官方 SPA 範例為 `csrf.spa()`（7.0 新增）；6.5 為 `CookieCsrfTokenRepository.withHttpOnlyFalse()`＋自訂 `SpaCsrfTokenRequestHandler`。
4. networknt json-schema-validator 3.0.8 依賴 tools.jackson 3.2.1，要求 Java 17，授權 "Apache License Version 2.0"。

**Q1 BYPASSRLS 角色（PG18）**
- 執行 CREATE ROLE："You must have `CREATEROLE` privilege or be a database superuser to use this command." [1]
- 指定 BYPASSRLS："Only superuser roles or roles with `BYPASSRLS` can specify `BYPASSRLS`." [1]
- "`CREATEROLE` does not confer the ability to grant or revoke the `BYPASSRLS` privilege."；"To create such a role, use `CREATE ROLE name BYPASSRLS` as a superuser." [2]
- 表擁有者："Table owners normally bypass row security as well"，可用 FORCE ROW LEVEL SECURITY 改變 [3]
- Azure："For Postgres 16 and later versioned servers ... azure_pg_admin ... allow you to create roles with the BYPASSRLS attribute"；Postgres 15 及以下："you can't create nonadmin users with the BypassRLS privilege" [4]
- RDS：postgres 角色為 "NOSUPERUSER"、含 CREATEROLE；官方頁未提 BYPASSRLS，查不到 [5]
- Cloud SQL："customers cannot create or have access to users with superuser attributes"；postgres 含 CREATEROLE、CREATEDB、LOGIN；未提 BYPASSRLS，查不到 [6]
- 建議：以目標平台實測 `CREATE ROLE ... BYPASSRLS` 後再定架構（建議）

**Q2 子交易溢位觀察（PG18）**
- pg_stat_slru 欄位：name（"Name of the SLRU"）、blks_zeroed、blks_hit、blks_read、blks_written、blks_exists、flushes、truncates、stats_reset [7]
- name 官方值（見 pg_stat_reset_slru 說明）：commit_timestamp、multixact_member、multixact_offset、notify、serializable、subtransaction、transaction [7]
- 設定參數：各 SLRU 的大小參數以 "_buffers" 結尾 [7]；AWS 稱 17.1 起可設 subtransaction_buffers（僅 AWS 文件，未由官方頁驗證）[8]
- pg_stat_activity：官方欄位表無 subxact 相關欄位，"subxact_overflowed" 不存在於官方頁 [7]
- pg_stat_get_backend_subxact(integer) 回傳 subxact_count 與 subxact_overflow [7]；如何由 pg_stat_activity 取得 backend ID，查不到
- 其他訊號（AWS，搜尋摘要未逐字驗證）：觀察 Subtrans 列 blks_read 是否持續增加；等待事件 LWLock:SubtransSLRU [8]

**Q3 Spring Security 7 SPA CSRF**
- 7.0 SPA 範例：`.csrf((csrf) -> csrf.spa());`（Kotlin `csrf { spa() }`）[9]
- 7.0 whats-new："Added support for SPA-based CSRF configuration" [10]
- 7.0 同頁另有 `CookieCsrfTokenRepository.withHttpOnlyFalse()`；"we _recommend_ omitting `HttpOnly`" 若 JS 不需讀 cookie [9]
- 6.5 範例（無 csrf.spa()）：`.csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())` ＋ `.csrfTokenRequestHandler(new SpaCsrfTokenRequestHandler())`，handler 內用 XorCsrfTokenRequestAttributeHandler 並呼叫 `csrfToken.get()` [11]
- 差異：7.0 新增 csrf.spa() 簡寫 [10]；csrf.spa() 內部是否等同 6.5 的自訂 handler，查不到；7.0 "自訂 handler"連結內容未取得 [9]
- 共通：cookie 存 token 時 JS 只拿到 plain 值；登入、登出成功後 cookie 被清除，需取得新 token [9][11]
- 7.0 migration 指南無 CSRF 條目 [12]

**Q4 Jackson 3 JSON Schema 驗證器**
- 最新版 3.0.8；lastUpdated 20261002030240；3.0.x 共 9 版（3.0.0～3.0.8）[13]
- 3.0.8 pom：tools.jackson.core:jackson-databind 3.2.1、tools.jackson.dataformat:jackson-dataformat-yaml 3.2.1；java.version 17；License "Apache License Version 2.0" [14]
- README 摘要："Compatible with Java 17+ and Jackson 3.x"；但摘要列的依賴為 com.fasterxml 座標，與 pom 不符，以 pom 為準 [15]
- 未查到：Jackson 3 專用 ObjectMapper 用法範例
